# 202609 Reliability & Auth Review — Task List

Started: 2026-09-26
Scope: Reliability and robustness of Microsoft Graph API calls, the initial
auth flow, and silent token refresh (auto re-auth) for personal Microsoft
accounts.

Legend: `[ ]` todo · `[~]` in progress · `[x]` done · `[-]` won't do

## Findings

- F1. **Root cause of the forced re-auth:** the refresh token expired after
  113 days idle (`AADSTS70000 grant is expired`). Personal-account refresh
  tokens expire after 90 days without use. The user re-authenticated on
  2026-09-26; silent refresh is verified working again.
- F2. `authenticate.py` lists cached accounts without checking their tokens,
  and prints "Authentication complete!" even when no account has a working
  token. Answering "n" looks like success but changes nothing.
- F3. The token cache (`~/.m365_mcp_token_cache.json`) is read and written
  with no lock and no atomic write. Concurrent tool calls, or several server
  processes (for example Claude Desktop and Claude Code each launching one),
  can overwrite or truncate each other's refreshed tokens.
- F4. `get_token()` builds a new `PublicClientApplication` on **every** Graph
  request. MSAL makes a network call to the login endpoint (tenant
  discovery) each time the app is built, so each request costs an extra
  round-trip and fails whenever that endpoint is briefly unavailable.
- F5. When a silent refresh fails, `get_token()` throws away the real MSAL
  error. An expired or revoked token (`invalid_grant`) and a transient
  failure produce the same generic "No cached Microsoft access token"
  message.
- F6. `account_complete_auth` calls `acquire_token_by_device_flow` without an
  exit condition, so MSAL keeps polling until the code expires (up to 15
  minutes). The tool blocks, and its "pending" branch is unreachable.
- F7. `graph.request()` never retries on a 401. A token revoked or expired
  mid-flight fails the call instead of being refreshed once with
  `force_refresh`.
- F8. `graph.request()` / `download_raw()` do not retry network errors
  (connect errors, timeouts). The `Authorization` header is built once
  before the retry loop, so the token can go stale during long 429 waits.
- F9. `int(Retry-After)` raises `ValueError` if Graph sends an HTTP-date.
  `Retry-After` on 503 is ignored.
- F10. Chunked uploads send an `Authorization` header to the pre-authenticated
  `uploadUrl`. Microsoft docs say not to, because it can cause 401s. The
  final mail-attachment chunk returns `201` with an empty body, and
  `response.json()` then raises.

## Tasks

### Auth

- [x] T1. `authenticate.py`: check each account with a silent refresh, show
  valid/expired, offer sign-in for expired accounts, only report success
  when a token was obtained. (F2)
- [x] T2. Token cache: use `msal-extensions` `PersistedTokenCache`, which
  gives cross-process file locking and reloads the cache when another
  process changes it. (F3)
- [x] T3. Reuse one MSAL app per (client_id, tenant) instead of building one
  per request. (F4)
- [x] T4. `get_token()`: surface the MSAL error. For `invalid_grant` /
  `interaction_required`, say the sign-in has expired and give the exact
  command to fix it. (F5)
- [x] T5. `account_complete_auth`: poll once (non-blocking) so "pending"
  works. (F6)

### Graph client

- [x] T6. On a 401, force-refresh the token once and retry. (F7)
- [x] T7. Retry transport errors: connect errors for any method; timeouts
  only for idempotent methods, so emails are never sent twice. Rebuild
  headers on each attempt. (F8)
- [x] T8. Parse `Retry-After` robustly and honour it on 503. (F9)
- [x] T9. Chunked upload: no `Authorization` header to `uploadUrl`; handle
  an empty 201 body. (F10)
- [x] T9a. Also made a behaviour change: POSTs are no longer retried on
  ambiguous 5xx (500/502/504) or on read timeouts, because the write may
  already have happened (for example an email sent twice). 429 and 503 are
  still retried for every method.
