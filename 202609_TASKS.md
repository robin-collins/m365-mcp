## A. v1.0.0 unified tools programme

Design: `UNIFIED_TOOLS_CONCEPT.md` §14 (phases 0–5). Target: 29 tools
(core 16, extended 7, admin 6), hard cut of all 85 legacy names, personal
accounts only.

### Phase 0 — Baseline

- [~] **U0.2** Build the golden-prompt evaluation harness (`evals/`):
  - 80–120 prompts: direct, indirect, ambiguous, competing-tool (list vs
    search, email_folder vs drive folder, update vs move) and no-tool;
  - a 25% held-out split;
  - a mocked Graph layer, so runs are deterministic and side-effect free;
  - a runner that presents a given tool surface to a Claude model (current
    default: `claude-sonnet-5`) and records the §16.2 metrics:
    - correct first tool;
    - first-try schema-valid arguments;
    - task success;
    - calls per task;
    - result tokens;
    - unconfirmed side-effect calls.

  *Gate:* harness runs end-to-end on a 10-prompt smoke set.

  Status: harness built in `evals/` (115 cases, 28 held out, fake Graph,
  runner, offline tests in `tests/test_evals_harness.py`). The live smoke
  run is waiting on Anthropic API credentials on this machine.
- [ ] **U0.3** Record the baseline on the 85-tool surface into
  `evals/results/baseline-v0.md`. *Gate:* metrics table committed.

### Phase 2 — Foundations

- [ ] **U2.1 Spec packaging.** Builder also writes `tools/*.json` and
  `index.json` to `src/m365_mcp/tool_specs/` as package data. Add a
  `pyproject.toml` include and a test that the package copy equals the docs
  copy. *Gate:* installed wheel contains the specs.
- [ ] **U2.2 Spec-driven registration** (`tools/registry.py`):
  - register each enabled tool from its spec JSON, with exact `name`,
    `title`, `description`, `annotations`, `meta`, `inputSchema` and
    `outputSchema`;
  - keep the fixed `index.json` order;
  - `M365_MCP_TOOLSETS` (default `core,extended`); unknown values fail at
    startup with a clear message.

  *Gate:* a conformance test compares live `tools/list` to the spec for
  toolsets {core}, {core,extended} and {core,extended,admin}; the list is
  byte-identical across two processes.
- [ ] **U2.3 Input validation pipeline.**
  - Draft 2020-12 validation with a format checker before every handler;
    schema errors are converted to
    `Invalid <param> '<value>': <reason>. Expected: <expected>`.
  - A hook runs each tool's semantic `validation_rules`.

  *Gate:* the invalid-input corpus from `test_unified_tool_specs.py` is
  rejected at runtime with actionable text.
- [ ] **U2.4 Output contract.** Handlers return typed dicts. A test-mode
  wrapper validates every `structuredContent` against `outputSchema`; the
  text content equals `summary`. *Gate:* output validation runs in all
  handler tests.
- [ ] **U2.5 `projections.py`.** Graph JSON → §5.2 records for `email`
  (summary/detail), `email_folder` (with tree), `email_rule`
  (camelCase↔snake_case for 30 predicates and 11 actions), `event`
  (summary/detail, `calendarView` shape), `calendar`, `contact`,
  `contact_folder`, `drive_item` (with tree) and `operation`. *Gate:* one
  fixture-based test per projection, validated against the spec `$defs`.
- [ ] **U2.6 `cursors.py`.** Opaque base64url cursor with version, account
  hash, resource, request hash, Graph nextLink or offset, and issued-at.
  Checks: host allowlist (`GRAPH_ALLOWED_HOSTS`), request-hash match and a
  24 h expiry. Multi-resource search carries per-resource sub-cursors.
  *Gate:* round-trip, tamper, expiry and wrong-request tests.
- [ ] **U2.7 `errors.py`.**
  - `GraphAPIError(status, code, message, request_id)` is raised from
    `graph._send` by parsing the Graph error body.
  - A mapping table converts it to `ToolError` text for 400, 401, 403, 404,
    409, 412, 413, 423, 429 (after retries) and 5xx, with correction
    hints and no URLs.
  - `FastMCP(mask_error_details=True)`.

  *Gate:* one test per status, plus an assertion that no URL appears in any
  message.
- [ ] **U2.8 JSON batching.** `graph.batch(requests)` via `POST /$batch`
  (≤ 20 per call), with per-item results, 429 items retried with
  Retry-After, and no retries for non-idempotent items. *Gate:*
  partial-failure and throttling tests.
- [ ] **U2.9 Deadline budget.** A per-call budget (reads 45 s, writes 60 s)
  checked before each retry or sleep in `_send`. Transfers are exempt but
  chunked. The error says to try again in N s. *Gate:* fake-clock tests.
- [ ] **U2.10 Account resolution.** `account_id` is optional; the single
  signed-in account is the default. With several accounts, the error lists
  ID and email. Accepts the ID or email. *Gate:* 0-, 1- and 2-account
  tests.
- [ ] **U2.11 Personal-only auth.**
  - Default authority `consumers` (`M365_MCP_TENANT_ID` default changed;
    `.env.example` updated).
  - Reject work/school accounts at sign-in completion.
  - Remove `account_type.py` and account-type metadata.
  - A device-flow session store: opaque `auth_session_id`, flow kept
    server-side, 15 min TTL.

  *Gate:* tests for rejection, session expiry, and no device code in tool
  output.
- [ ] **U2.12 Cache re-keying.**
  - Keys are (account, resource, normalised params, cursor), with TTL
    policies per resource.
  - Mutations invalidate the matching resource keys for that account only.
  - `refresh=true` bypasses the cache.
  - No cache metadata in results.
  - `admin_cache_invalidate(scope)` maps to the resource keys.

  *Gate:* cache tests updated; invalidation-matrix test per mutating tool.
- [ ] **U2.13 Local file safety.** Allowed roots plus a deny-list (hidden
  files, `.env`, `*.pem`, `*.key`, `*token_cache*`) for both read and
  write; `overwrite=false` protection; file-name sanitisation. *Gate:*
  traversal, symlink, deny-list and overwrite tests.
- [ ] **U2.14 Rate limiting.** Per-account token buckets: sends, shares and
  deletes ≤ 20/min; all calls ≤ 300/min; an actionable error. *Gate:*
  fake-clock tests.
- [ ] **U2.15 Observability and instructions.**
  - A FastMCP middleware emits one JSON log line per call: tool, resource,
    hashed account, duration, outcome and error class, retries, result
    bytes, mutation flag. It never logs tokens, URLs or passwords.
  - The server `instructions` text comes from concept §12.4.

  *Gate:* a log-shape test and a secret-redaction test.
- [ ] **U2.16 Operation store.** Records `drive_copy` monitor URLs
  server-side with a 24 h TTL. Polling uses no `Authorization` header.
  *Gate:* status transition tests (in_progress → completed / failed).
- [ ] **U2.17 Untrusted content.** Strip control characters, HTML → text
  fallback, and body caps. The untrusted fields match the spec
  descriptions. *Gate:* sanitisation tests, including a prompt-injection
  fixture.
